# 0.1.0

0.1.0: the minimal fixture, a character file, goes through the checked
reader to SVG and to a Godot render whose pixels match the SVG reference
within set thresholds, then publish, in the container, locally and in CI;
its joint is driven by Skeleton2D within its limits; only checked JSON ever
enters the container; a packed tarball installs cleanly and reads a
character; Godot is a required check proven by a broken pull request; the
privacy defences and the reader's hostile-input refusals each run in a
named check.

## Order

- A, C and D can start at once: C and D touch nothing A does.
- B follows A and lands before any asset is pushed.
- B2 lands before any pull request carrying assets is pushed, so E's pull
  request waits for it. One concern: #26 and #28 both change what the
  privacy check scans, in the same two files.
- D3 can start at once: it alone touches `container/` now that D2 is merged.
- D2 and E can start at once: they share no files.
- E2 and E3 run in parallel after E: E2 alone touches `commands.ts`; E3
  adds no command.
- F follows D2, E2 and E3.
- G and H run in parallel after F: G alone touches root `package.json`, H
  alone the CLI's.
- I comes last and reruns every check on the merged result.

## Rules for this milestone

- Admin merges (the judge guards scripts, workflows and install settings):
  A, G, H and I. H is admin because building and packing the CLI adds
  package scripts. A refusal on any other phase is diagnosed, not bypassed.
- B2 and D3 change checks the judge does not guard, so they merge normally,
  each after the owner's yes.
- Each phase is one pull request closing one issue. A phase over the size
  limits splits, or carries a real `One concern:` reason.
- Delicate phases get an adversarial review of their brief before building,
  and a re-check of the revised brief.
- Every pull request gets a security note: downloads and pins, new
  dependencies and their source, CLI input, filesystem writes.
- Shared files (root and CLI `package.json`, the lockfile, `tsconfig.json`,
  `eslint.config.js`) are changed by the orchestrator, including E's
  `typescript` runtime dependency and E2's `@resvg/resvg-js` dev
  dependency.
- The reader's hostile-input tests run in the gate; the builder's tests
  and the render comparison run in `check:godot`.
- The owner reviews every asset, and the outgoing files of each pull
  request, before it is pushed.
