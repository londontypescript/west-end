# 0.1.0

0.1.0: the minimal fixture, a character file, goes through the checked
reader to SVG and to a Godot render whose pixels match the SVG reference
within set thresholds, then publish, in the container, locally and in CI;
its joint is driven by Skeleton2D within its limits; only checked JSON ever
enters the container; a packed tarball installs cleanly and reads a
character; Godot is a required check proven by a broken pull request; the
privacy defences and the reader's hostile-input refusals each run in a
named check.

## Phase E landing order

Phase E lands through dependency-ordered pull requests under #5. Land one
at a time in the order below. “After” names the code prerequisites.
Each intermediate change keeps the existing CLI behaviour. Keep incomplete
reader stages internal and test them directly. Expose the checked reader
only once validation is complete.

| Unit                 | Rating   | After                                    | Ownership and verification                                                                                                     |
| -------------------- | -------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Bounded syntax       | Delicate | A, B2                                    | Scanner and in-memory compiler host, relevant error/budget declarations, pinned TypeScript dependency and host isolation tests |
| Literal values       | Delicate | Bounded syntax                           | AST literal conversion, immutable values, source locations, repeated and forbidden keys, syntax-to-value tests                 |
| Field primitives     | Involved | Literal values                           | Character types and reusable scalar, tuple and command validators with focused tests                                           |
| Character schema     | Delicate | Field primitives                         | Top-level and node validation, known fields and permitted rig content, relevant fixtures                                       |
| Reference graphs     | Delicate | Character schema                         | Reference resolution, dependency order and cycles, with isolated graph tests                                                   |
| Structure and paths  | Delicate | Reference graphs                         | Expanded budgets, names, look selections, diagnostic traces                                                                    |
| Geometry primitives  | Delicate | Field primitives                         | Curve flattening and geometric rules, tested directly                                                                          |
| Placement validation | Delicate | Geometry primitives, structure and paths | Placement context, geometry work budgets, full reader integration and end-to-end refusals                                      |
| Resolved geometry    | Involved | Field primitives                         | Coordinate mapping, transformed paths and authored bounds with numeric tests                                                   |
| Rig resolution       | Delicate | Placement validation, resolved geometry  | Resolved records, templates, draw order, authored default and clip owner                                                       |
| Rigid poses          | Delicate | Rig resolution                           | Authored pose validation and resolved angles, regression checks and final reader contract                                      |

Measure each staged diff with the pinned size check. If a slice exceeds
the limits, split it at a tested interface. Add refusal fixtures with the
checks they exercise. Add the approved character fixtures and provenance
with the first reader slice that fully validates them.

The resolver preserves the authored default variant and the frame that
owns each clip. The wire writer uses bounded shared clip references. The
pose slice implements ADR 0013 and bounds angles for joints without authored
limits. Pose validation covers mirrored paths, overrides and wrong target
kinds. Prove contour union in the downstream renderers.

Each slice passes the pinned gate, has break-it evidence for each new
check and receives independent review. The final slice closes #5. E2 and
E3 start after it lands.

## Order

- A, C and D can start at once: C and D touch nothing A does.
- B follows A and lands before any asset is pushed.
- B2 lands before any pull request carrying assets is pushed, so E's asset
  changes wait for it. One concern: #26 and #28 both change what the
  privacy check scans, in the same two files.
- D3 can start at once: it alone touches `container/` now that D2 is merged.
- D2 and E can start at once: they share no files.
- E2 and E3 run in parallel after E: E2 alone touches `commands.ts`; E3
  adds no command.
- F follows D2, E2 and E3.
- G and H run in parallel after F: G alone touches root `package.json`, H
  alone the CLI's.
- I comes last and reruns every check on the merged result.

## Rules for this milestone

- Admin merges (the judge guards scripts, workflows and install settings):
  A, G, H and I. H is admin because building and packing the CLI adds
  package scripts. A refusal on any other phase is diagnosed, not bypassed.
- B2 and D3 change checks the judge does not guard, so they merge normally,
  each after the owner's yes.
- Each phase normally lands in one pull request closing one issue. Phase E
  lands in the slices above. A change over the size limits splits, or
  carries a real `One concern:` reason.
- Delicate phases get an adversarial review of their brief before building,
  and a re-check of the revised brief.
- Every pull request gets a security note: downloads and pins, new
  dependencies and their source, CLI input, filesystem writes.
- Shared files (root and CLI `package.json`, the lockfile, `tsconfig.json`,
  `eslint.config.js`) are changed by the orchestrator, including E's
  `typescript` runtime dependency and E2's `@resvg/resvg-js` dev
  dependency.
- The reader's hostile-input tests run in the gate; the builder's tests
  and the render comparison run in `check:godot`.
- The owner reviews every asset, and the outgoing files of each pull
  request, before it is pushed.
